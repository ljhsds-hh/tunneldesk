# 需求规格：Azure Bastion 连接方式（v0.2）

- 日期：2026-11-10
- 状态：需求已对齐，v0.2 已实现
- 关联文档：`2026-11-04-tunneldesk-design.md`（v0.1 基线）
- 需求来源：2026-11-10 对话，用户口述 + 6 轮澄清

---

## 0. 背景

当前 TunnelDesk 只支持一种连接方式：**直连 SSH**（填 `host` + `port` + 账号密码，首次密码换密钥）。

在新环境中该方式不可用：

| 路径 | 现状 |
| --- | --- |
| A → B 直连 `22` | **失败**。公司环境未对 B 的 SSH 端口开放入站（NSG/网络层拦截），属正常状态 |
| A → `127.0.0.1:50022` → Azure Bastion → B:22 | **正常**。隧道由 `az` CLI 建立，不需要改动 NSG / Bastion / VM 配置 |

目前 `50022` 隧道是用户在程序外部手工执行的（写进 `.bat` 双击运行）。本次要把这一层收进 TunnelDesk 内部，并新增「远程桌面」能力。

---

## 1. 硬约束（必须遵守）

| 编号 | 约束 | 说明 |
| --- | --- | --- |
| C1 | **零泄漏** | Bastion 名称 / 资源组 / VM 资源 ID 属公司敏感信息。**仓库内任何文件、提交信息、代码注释、测试夹具都不得出现这三类真实值**，一个字符都不行。配置只存 `%APPDATA%\TunnelDesk\`（仓库外） |
| C2 | **单实例** | 一台电脑只允许配置**一套** Bastion 配置，且只能操作它对应的那一台 VM。不支持在一个程序里切换不同 VM。目的是限制误操作范围 |
| C3 | **配置先行** | 选择「微软方式」连接前，必须先完成 Bastion 配置；未配置则不允许创建该类主机 |
| C4 | **不改 Azure 侧** | 不修改 VM / NSG / Bastion / 入站规则；不注册服务、不新增 B 侧监听端口 |
| C5 | **密码不落明文** | RDP 密码只能以 Windows DPAPI 密文形式存储与使用；SSH 密码沿用现有设计，只在首次换密钥时使用一次，不保存 |

## 2. 功能需求

### FR-1 连接方式二选一

- 新建主机时选择连接方式：`SSH`（直连）或 `Azure Bastion`（微软方式）。
- **SSH**：现有流程、校验、密码换密钥逻辑**完全不变**。
- **Azure Bastion**：
  - 地址固定 `127.0.0.1`，端口固定 `50022`，界面只读展示，不允许编辑。
  - 未配置 Bastion 时，选择该方式即被拦截，并引导先完成配置。
  - 仍需填写 B 的 Windows 账号与密码（仅用于首次 SSH 换密钥，密码不保存）；RDP 用的账号密码在 Bastion 配置里单独填写（见 FR-2）。
- 已存在的主机保持 `SSH` 不变（见 FR-8）；编辑主机时允许切换连接方式，切换时**保留已安装的密钥与指纹**。
- 微软方式主机数量不限制，但都指向同一台 VM、共用同一条 50022 隧道；实际使用建议只保留一台。

### FR-2 Bastion 配置（全局唯一）

| 项 | 要求 |
| --- | --- |
| 输入字段 | 仅 3 个：Bastion 名称、资源组、VM 资源 ID。**命令其余部分由程序内置**，用户不接触 |
| 附加字段 | RDP 账号、RDP 密码（密码 DPAPI 加密后保存）。两项均允许留空；留空时 `.rdp` 不预填对应内容，交由 Windows 弹窗要求输入 |
| 存储位置 | `%APPDATA%\TunnelDesk\config.json`（仓库外） |
| 数量 | 唯一一份；不提供新增第二套的入口 |
| 修改/重置 | 允许，但需二次确认；重置时清理关联的隧道进程与生成的 `.rdp`。修改后，已存在的微软方式主机需重新测试登录（旧密钥/指纹不再适用） |
| 展示 | 已保存的值默认打码显示（如 `abcd…wxyz`），需要时手动展开 |
| 下发范围 | 下发给前端的状态中**不得包含密码密文**，只提供「是否已保存密码」的布尔标记；三个参数值只允许出现在配置卡片内 |
| 校验 | 保存时只做非空/格式校验，不做联网校验（避免在无 az 环境误报） |

内置命令前缀（程序拼装，参数值来自配置）：

```text
az network bastion tunnel --name <Bastion> --resource-group <RG> \
  --target-resource-id <VM> --resource-port <资源端口> --port <本地端口>
```

> 说明：远程桌面采用「3389 隧道 + 自建 `.rdp`」实现（见 FR-3），因此内置前缀为 `tunnel` 而非 `rdp --configure`；三个参数与用户提供的一致。

### FR-3 远程桌面（手动触发）

> 用户口中的「一键启动虚拟机」即本动作：打开远程桌面窗口，**不是** `az vm start` 开机。

- **默认不启动**：只能由用户点击按钮触发；程序启动、重连、切页都**不得**自动弹出桌面。
- 执行流程：
  1. 选一个空闲本地端口（不固定，避免冲突）。
  2. 启动 `az` 隧道：`--resource-port 3389 --port <本地端口>`。
  3. TCP 探测本地端口就绪（超时则报错，不得静默）。
  4. 生成 `.rdp` 到 `%APPDATA%\TunnelDesk\rdp\`，内容包含：`full address:s:127.0.0.1:<端口>`、预填账号、DPAPI 密文密码、关闭凭据提示。
  5. 启动 `mstsc` 打开该 `.rdp`。
- 生命周期：
  - 用户关闭 RDP 窗口 → 对应隧道自动回收。
  - 关闭 TunnelDesk → 终止所有 RDP 隧道，**桌面连接随之断开**（已确认可接受）。
  - 程序退出时删除本次生成的 `.rdp` 文件，不长期留存。
- 允许重复点击：每次生成独立隧道与独立窗口，互不影响。
- 与 SSH 解耦：远程桌面不依赖 SSH 是否在线，也不依赖 50022 是否运行；两者互不影响。
- 失败处理：隧道起不来、端口探测超时、`.rdp` 写入失败、mstsc 启动失败，均需在界面给出明确原因 + 诊断输出。

### FR-4 50022 隧道（程序托管）

| 项 | 要求 |
| --- | --- |
| 端口 | **固定 50022**，专用，不提供修改入口 |
| 资源端口 | 固定 22 |
| 前置检查 | 启动前依次确认：`az` 可执行 → 已登录（未登录则明确提示执行 `az login`）→ 50022 端口空闲 |
| 默认行为 | **默认自动启动**（程序启动时若主机为微软方式则自动起隧道）；可在配置中改为默认关闭 |
| 默认关闭时 | `autoStartTunnel` 为关闭时不自动拉起隧道，**也不发起 SSH 连接**；界面明确提示「请先启动 50022」 |
| 手动停止 | 提供「停止 50022」动作：终止隧道并断开 SSH，状态回到「未启动」；再次点击可重新拉起 |
| 就绪判定 | 以「本地 50022 可建立 TCP 连接」为准，不依赖解析 az 输出文本 |
| 与 SSH 的关系 | 隧道就绪后才允许任何 SSH 操作（**含首次换密钥、测试登录、正常连接**）；隧道未就绪时不发起 SSH，避免必然失败的重试风暴。创建微软方式主机时若隧道未启动，先拉起隧道再换密钥 |
| 端口占用 | 启动前检测。被占用时：报「连接失败：端口 50022 被 `<进程名>(PID)` 占用」，并提供「一键停止并重连」；停止成功后重新拉起隧道并连接 |
| 进程异常退出 | 指数退避自动重拉（1s → 2s → 4s → 8s → 15s → 30s），连续 5 次失败后停止并报错，等待用户手动重试 |
| 关闭程序 | 终止程序自己拉起的 50022 进程（含 `az.cmd` 派生的子进程树），确保无残留 |
| 幂等 | 已启动时重复点击不重复拉起 |

### FR-5 SSH 登录（沿用现有能力）

- 微软模式只是把目标从「B 的 IP:22」换成「`127.0.0.1:50022`」，其余逻辑**不新增、不改动**：
  - 首次密码换 RSA-3072 密钥、无 BOM 写入 `authorized_keys`、管理员写 `administrators_authorized_keys` + ACL、写后立即用密钥复测；
  - 失败不保存主机并删除私钥；
  - 指纹 TOFU；
  - 离线时本地监听保持占用并快速拒绝连接；
  - 自动重连沿用现有 `settings.reconnect`。
- 凭据分离（按用户要求）：
  - **RDP 账号/密码**：存在 Bastion 配置中，持久化（密码 DPAPI）。
  - **SSH 账号**：存在主机记录中；**密码只在首次换密钥时使用一次，不持久化**（与 v0.1 一致）。
  - 两者即使相同也各存各的，互不覆盖；不同也不影响。

### FR-6 诊断与可观测

- 新增可折叠的「`az` 诊断输出」面板：显示最近 200 行 stdout/stderr，**打码后**展示。
- 日志文件不记录完整命令行（含三个参数值），只记录「启动/停止/退出码/是否就绪」这类元信息。
- 打码规则：三个配置值在日志、错误信息、诊断输出中一律替换为 `***`；配置卡片里默认打码，提供「显示」按钮供本人核对。
- 隧道状态在界面上可区分：未启动 / 启动中 / 就绪 / 重连中 / 失败（含失败原因）。

### FR-7 配置模型与迁移

- `HostConfig` 新增 `connectionType: 'ssh' | 'azure-bastion'`，缺省 `ssh`。
- `AppConfig` 新增 `bastion: BastionProfile | null`（全局唯一）。
- `BastionProfile` 字段：`name`、`resourceGroup`、`targetResourceId`、`rdpUsername`、`rdpPasswordCipher`、`autoStartTunnel`、`updatedAt`。
- 配置版本号提升；读取旧配置时补齐默认值（现有主机全部视为 `ssh`，`bastion = null`）。
- 原子写、损坏备份并回退默认的行为保持不变。

### FR-8 兼容性

- 现有主机记录、映射、代理、PAC、防火墙规则逻辑均不受影响。
- 现有主机默认按 `SSH` 处理，不需要用户重新配置。
- 若用户希望把现有 `127.0.0.1:50022` 主机改为微软方式，可在「编辑主机」里切换，密钥与指纹保留。
- 现有接口只有「重命名/删除主机」，为支持切换需新增一个「更新主机连接方式」接口，字段限定为 `connectionType` 与地址/端口，不得触碰 `keyPath` / `hostKeyFingerprint`。

### 5.2 需用户在真实环境验证

1. 保存 Bastion 配置 → 刷新后仍在，且默认打码。
2. 未配置时选微软方式被拦截；配置后可创建主机，地址端口为只读的 `127.0.0.1:50022`。
3. 首次连接：自动起 50022 → 就绪后连 SSH → 密码换密钥成功。
4. 关闭并重启程序：自动起隧道并自动连接（若 `autoStartTunnel` 开启）。
5. 点「远程桌面」→ 弹出 RDP 窗口，账号已预填、**不需要输密码** → 能进入桌面。
6. 关闭 RDP 窗口 → 对应隧道进程消失，50022 不受影响。
7. 手工占用 50022 → 显示占用进程并给出「一键停止并重连」，执行后恢复正常。
8. 杀掉 50022 的 `az` 进程 → 自动重拉并恢复 SSH。
9. 关闭 TunnelDesk → 50022 与 RDP 隧道进程均消失，无残留 `az`。
10. 原 SSH 方式主机行为与之前完全一致。
11. 未安装 `az` 或未执行 `az login` 时，界面给出明确提示而不是无反应或空白错误。
12. 把 `autoStartTunnel` 改为关闭后重启：不自动起隧道、不自动连 SSH，界面提示「请先启动 50022」；手动启动后能正常连接。

### 5.3 环境前提（用户侧）

- 测试机安装 Azure CLI（≥ 2.32，`az network bastion` 可用）并已完成 `az login`，`az` 在 PATH 中。
- Bastion 为标准 SKU 且已启用 native client。
- B 侧 3389 与 22 可经隧道访问（已验证通过）。

## 6. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 开发机无 `az`、无真实环境，无法端到端验证 | 行为偏差只能靠用户发现 | 就绪判断用 TCP 探测而非解析输出；界面提供诊断输出；验收清单逐条给出 |
| `az` 输出可能带出资源 ID | 敏感信息进日志/界面 | 统一打码函数，所有出口过滤；单测覆盖 |
| `mstsc` 进程生命周期判断不准 | 隧道残留或提前回收 | 以 mstsc 子进程退出为准，并在程序退出时兜底清理全部隧道 |
| 配置中存密文密码 | 安全争议 | DPAPI 用户级加密，密文换机器/账号无法解密；界面不提供明文查看 |
| DPAPI 加解密需调用 PowerShell | 编码/引号处理不当会损坏密文 | 固定使用 `-EncodedCommand`（Base64 UTF-16LE）调用，避免中文与引号转义；单测覆盖加密→解密往返 |
| 多个订阅 / 默认订阅不对 | 命令失败 | 错误原文透出（打码）并提示检查 `az account set` |
| 前后端配置版本不一致 | 旧配置读取异常 | 读取时补齐默认值，损坏则备份并回退 |
